# Migration Assistant: the envelope → RFC 9457 problem details as the default error shape

- ID: `MA-2026-022`
- Pairs with: `docs/deprecations/DEP-2026-022-problem-details-default-error-shape.md`
- Severity: `high` at v2.0.0 for applications that chose nothing and have
  clients parsing `{"error": {...}}`; `low` before it (one option).
- Status: `current`

---

## Scope

Applications built without `WithProblemDetails()` and without
`WithErrorEnvelope()`, and the clients of their errors.

Out of scope: applications that already pass one of the two options.

## Detection

```bash
grep -n 'WithProblemDetails\|WithErrorEnvelope' main.go cmd/*/main.go internal/**/app.go 2>/dev/null || echo "neither: the default applies"
```

At run time, `App.ProblemDetails()` and `App.ErrorEnvelope()` both false.

## Rewrite

| Before | After | Kind |
|---|---|---|
| neither option, today's shape wanted | `nucleus.New().WithErrorEnvelope()` / `app.New(cfg, app.WithErrorEnvelope())` | manual (one call) |
| neither option, the standard shape wanted early | `nucleus.New().WithProblemDetails()` | manual (one call) |
| a client that reads `body.error.code` / `body.error.message` | read `Content-Type`; on `application/problem+json` take `title`, `detail`, `status` and the extension members `code` and `details`; keep the envelope branch | manual |

A TypeScript client generated by `nucleus openapi` already types both shapes
from the derived document.

## Verification

```bash
go test ./...                                          # the application's own error tests
curl -i http://localhost:8080/api/does-not-exist       # Content-Type says which shape answered
curl -i -H 'Accept: application/problem+json' http://localhost:8080/api/does-not-exist
```

## Rollback

`WithErrorEnvelope()` restores today's shape at any version.
